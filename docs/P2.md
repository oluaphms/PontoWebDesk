# P2 — Scale Ready (200–500+ empresas)

**Prioridade:** média (após P1)  
**Esta fase NÃO está implementada** — apenas planejada

## Objetivo

Preparar o SaaS para **centenas de empresas**: worker fora do HTTP, rotas de domínio nos hot paths, FE manutenível, sessão endurecida, LGPD operacional no path VPS e fim do ruído legado.

## Impacto

| Área | Ganho |
|------|--------|
| Escalabilidade | Ingest/AFD/cálculo não competem com request HTTP |
| Arquitetura API | Menos `/api/data` genérico nos caminhos críticos |
| Manutenibilidade | God-pages quebradas; virtualização |
| Compliance | DSR export/erase no path real LOCAL_API |
| Clareza ops | Um schema canônico; sem `supabase_old` no fluxo |

## Risco

| Item | Risco | Mitigação |
|------|-------|-----------|
| Worker | Jobs duplicados / lost | Idempotência; dead-letter já existente |
| Migrar `/api/data` | Regressão FE | Rotas aditivas; feature flag; fallback |
| Split god-pages | Conflitos de merge | Extrair hooks sem mudar UX |
| Refresh token | Sessão / CSRF | Seguir `docs/security/AUTH_HARDENING_SPRINTS.md` |
| LGPD | Overclaim vs implementação | Só o que o contrato vende |

## Itens (ordem de execução)

### P2.1 — Worker dedicado (promote / AFD / CALC_DAY)
- Fora do processo HTTP; PM2 cluster ou 2+ nós

### P2.2 — Hot reads fora de `/api/data`
- `time_records` / jornada → rotas de domínio

### P2.3 — Quebrar god-pages + virtualizar listas
- Timesheet, Employees, RepDevices; virtualização admin

### P2.4 — Refresh / rotação de sessão VPS
- Sem quebrar `AuthSessionProvider` / cookie CSRF

### P2.5 — LGPD DSR no path VPS
- Export/erase alinhado ao contrato

### P2.6 — Remover `supabase_old` do path operacional
- Arquivar off-repo; docs apontam só `supabase/migrations` + VPS

## Dependências

- **P0 + P1** estáveis em produção
- Capacidade de operar 2 processos (API + worker)
- Revisão jurídica mínima para DSR (escopo do contrato)

## Critério de aceite

- [ ] Promote/AFD/CALC não bloqueiam HTTP sob pico
- [ ] Espelho/jornada/hot employee reads sem depender de `/api/data` genérico
- [ ] Páginas alvo &lt; complexidade anterior; listas grandes virtualizadas ou paginadas server-side
- [ ] Refresh/rotação em prod sem logout em massa indevido
- [ ] DSR export/erase funciona no path VPS com evidência
- [ ] `supabase_old` fora do tree operacional; docs canônicos únicos

## Rollback

| Item | Rollback |
|------|----------|
| Worker | Processar no HTTP (async flag) temporariamente |
| Rotas domínio | FE volta a `/api/data` nas flags |
| Split pages | Reverter PRs de extração |
| Auth refresh | Desligar rotação; TTL access atual |
| LGPD | Feature off; manter schema |
| supabase_old | Restaurar do archive se necessário (não runtime) |
