# P0.1 — Relatório RLS Fail-Closed

## Objetivo

Eliminar fail-open quando `VPS_RLS_ENFORCED=true` e `app.current_company_id` estiver vazio.

## Policies analisadas

| Origem | Achado |
|--------|--------|
| `016_vps_rls_tenant_isolation.sql` — `vps_tenant_row_visible` | Com enforced=true e company vazio → **`ELSE true`** (fail-open) |
| Policies `vps_%_tenant` nas tabelas listadas em 016 | USING/WITH CHECK via `vps_tenant_row_visible(company_id::text)` |
| `006_rls_tenant_policies.sql` | Template; não altera runtime sozinho |
| Histórico Supabase `*rls*` | Fora do path VPS LOCAL_API; inventariado em `docs/architecture/policies-inventory.md` |

## Policies / função alteradas

| Item | Antes | Depois |
|------|-------|--------|
| `vps_tenant_row_visible` (migration **017**) | ELSE true | **ELSE false** (deny) |
| Comportamento com `VPS_RLS_ENFORCED=false` | Permite tudo | **Inalterado** |

## Flag

- `VPS_RLS_ENFORCED` — permanece **desabilitada** em development (default).
- Produção: habilitar **somente após** aplicar 016+017 e smoke cross-tenant.

## Riscos eliminados

- Sessão com RLS “ligado” mas sem `company_id` no `set_config` **não** vê mais todas as linhas.
- Reduz vazamento cross-tenant por bug de contexto vazio.

## Riscos remanescentes / pendências

- RLS VPS cobre **subset** de tabelas (lista 016) — tabelas fora da lista dependem só da API.
- Flag ainda off em prod até smoke (intencional).
- Supabase legado / `api/*` não é coberto por esta policy VPS.

## Como aplicar

```bash
cd backend
# DATABASE_URL apontando para o alvo
node scripts/apply-migrations.mjs
# ou aplicar só 017 manualmente via psql
```

Depois (staging/prod): `VPS_RLS_ENFORCED=true` + restart API.
