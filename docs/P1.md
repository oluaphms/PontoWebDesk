# P1 — Growth Ready (50–150 empresas)

**Prioridade:** alta (após P0 aceito)  
**Esta fase NÃO está implementada** — apenas planejada

## Objetivo

Estabilizar o produto sob **crescimento orgânico**: menos payload no FE, SQL alinhado a índices, schema lifecycle seguro, erros visíveis e operação mínima monitorada.

## Impacto

| Área | Ganho |
|------|--------|
| Performance FE/API | Listas de employees e hot paths mais leves |
| DB | Índices compostos efetivos (sem `company_id::text`) |
| Ops | Migrations VPS idempotentes; alertas mínimos |
| Confiabilidade | Folha/espelho não “some” por `.catch(() => [])` |

## Risco

| Item | Risco | Mitigação |
|------|-------|-----------|
| Default limit employees | Telas que assumem lista completa | Migrar consumidores para `fetchEmployeesPage` / typeahead |
| Tipagem UUID | Planos de query diferentes | `EXPLAIN` antes/depois; feature por rota |
| Migration ledger | Apply interrompido mid-flight | Backup pré-migrate; dry-run staging |
| Erros attendance | UI mostra erro onde antes via vazio | `meta.degraded` + UX controlada |

## Itens (ordem de execução)

### P1.1 — Default employees 50–100 + typeahead
- Reduzir default de listagem clássica (hoje até 1000)
- Todos os consumidores admin usam página/busca

### P1.2 — Predicados `company_id` tipados (UUID)
- Remover `company_id::text` nos hot paths
- Validar com `EXPLAIN` + índices `20260712180000`

### P1.3 — Migration ledger na VPS
- Tabela `schema_migrations` (ou equivalente)
- `apply-migrations.mjs` idempotente

### P1.4 — Erros parciais em attendance/period
- Propagar falha / `meta.degraded` em vez de lista vazia silenciosa

### P1.5 — Semver + artefato de release da API
- Tags; tarball ou imagem versionada; runbook rollback &lt; 15 min

### P1.6 — Alertas mínimos
- Health DB, taxa 5xx, fila REP pending, latência ingest, disco upload

## Dependências

- **P0 concluído** (especialmente async REP e RLS estável)
- Índices SaaS já aplicados em prod (`20260712180000_saas_scale_tenant_indexes.sql`)
- Acesso a logs/métricas da VPS

## Critério de aceite

- [ ] Nenhum hot path admin carrega 1000 employees por default
- [ ] Hot SQL usa UUID nativo; `EXPLAIN` sem seq scan injustificado nos predicados tenant
- [ ] Reaplicar migrations VPS é seguro (ledger)
- [ ] Falha parcial de período aparece como degradado/erro, não espelho vazio silencioso
- [ ] Release API tagueada; rollback documentado &lt; 15 min
- [ ] Alertas mínimos disparando em smoke artificial

## Rollback

| Item | Rollback |
|------|----------|
| Limit employees | Restaurar default 1000 via env/flag se necessário |
| UUID predicates | Reverter commit SQL/controllers |
| Ledger | Manter ledger; não apagar histórico; hotfix script |
| Attendance meta | Flag para comportamento antigo só se crítico |
| Release | Redeploy tag anterior |
| Alertas | Desligar canal; manter health |
